# 07 · 无障碍：让"看不见字"的人也办得成事

> 低识字人群的障碍不是"字小"，是**读不懂 + 不敢确认**。所以不能只放大字号，要把"听"和"说"接进来。

## 三层一起给

| 层 | 做法 | 断言 |
|---|---|---|
| 输出 | Agent 每条回复自动播报；也可点消息旁的 🔊 单条朗读 | `speech.金额读成中文`、`speech.确认卡说的是人话` |
| 输入 | 🎤 说话 → 浏览器语音识别 → 直接进 `handleUserText()` | `结构.index.html 骨架完整`（含 `startVoiceInput`） |
| 确认 | 大字一句话"给「小王」转 300.00 元，对吗？" + 「对，就这样 / 不对，取消」 | `speech.确认卡说的是人话` |

## 播报不是"把 HTML 念一遍"

`toSpeechText()` 做三件事：

1. **金额读成中文**：`5,000.00 元` → `五千元`；`1234.56 元` → `一千二百三十四元五角六分`（有断言，含角分）；
2. **去掉符号与表情**：🟢🔴 这类图标对听的人没有信息量，反而打断；
3. **去掉括号里的补充说明**：老人听一句话就够，括号是给读的人看的。

`speak()` 的纪律：**没有语音引擎就返回 `false`，绝不假装播报过**（断言 `speech.没有语音能力就返回 false`）。

## 离线约束（如实说明）

| 能力 | 依赖 | 断网时 |
|---|---|---|
| 语音播报 TTS | 浏览器 `speechSynthesis` + 系统语音包 | Windows 的系统语音可离线；Chrome 若只挂了云端语音则无声，`speak()` 返回 false，界面照常可用 |
| 语音输入 ASR | Chrome/Edge 的 Web Speech 识别 | **需要联网**；不可用时明确提示"这个浏览器不支持语音输入，可以点常用说法或让家人帮忙打字" |

所以演示时必须说清楚：**语音是增强通道，文字链路始终在**。评委问"断网怎么办"，答案是"文字照跑，语音降级，且降级会说出来"。

## 为什么确认环节要"说人话"

原来的按钮是「确认执行 / 取消」——不识字的人分不清哪个是"同意"。现在：

- 一句话摘要放最大：`给「小王」转 300.00 元，对吗？`
- 按钮改成 `对，就这样` / `不对，取消`
- 摘要同时播报（`if (AUTO_SPEAK) speak(ask)`）

这条和判定层是解耦的：**改文案不改变权限结论**，红级照样拦、黄级照样要确认。

## 补上的四条（v0.7.0）

| 缺口 | 现在做到什么 | 边界（必须说清楚） |
|---|---|---|
| 逐步引导 | 🧭「一步步办」：一次只问一件事，每步只给 3 个按钮（人 → 金额），问完才成单 | 真能力 |
| 纯图标确认 | 🖼「图标模式」：头像首字 + 超大金额 + ✔/✘，确认卡里没有一句长文 | 真能力 |
| 电话通道 | 📞「电话模式」：模拟来电界面，1 确认 / 2 取消 / 0 重听 / 9 转人工，全程语音播报 | **模拟交互**；真实接入需 SIP/IVR 网关 |
| 方言口音 | `DIALECT_MAP` 词表（畀→转给、蚊→元、幾多→多少…）+ 语音语言可切 | **不是方言语音识别**，认不出的仍走"不理解" |

三条设计细节：

1. **引导最后仍走同一条链路**：`handleUserText('转给小王 500 元')`——引导只是"把话问清楚"，判定、确认、审计一行没改（断言 `guide.引导仍走同一判定链路`）。
2. **电话通道有额度上限**：`金额 > 单笔限额` 直接拒绝（"请打开手机或到柜面"）。音频通道更容易被冒充，不能给它和大额同等的权限（断言 `ivr.大额不在电话里办`）。
3. **图标模式不改判定**：只是换呈现，红级照样拦。

## 仍然缺的（更硬的四条）

1. **真实电话网关**：现在只是交互模拟，拨号、ASR/TTS 走运营商线路、通话录音留证，都需要 SIP/IVR 与号码资源；
2. **方言语音识别**：词表只覆盖文本层，真正的方言 ASR 需要专门声学模型，浏览器 Web Speech 做不到；
3. **真机与真人测试**：所有断言都是逻辑层，没有找过低识字用户做可用性测试——这是最大的空白；
4. **语音引擎的离线可用性未验证**：`speak()` 会如实返回 false，但"某台具体机器上到底有没有中文语音包"只能在目标机器上验。
