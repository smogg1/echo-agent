# 08 · 意图层：为什么现在"不够智能"，以及怎么变聪明

## 现状：不是模型笨，是架构里没给智能留位置

`parseIntent()` 是一串 `if (/正则/)` 顺序返回。它的能力上限 = **我列了多少条规则、顺序对不对**。

四个已知症状，全部源自同一个机制：

| 症状 | 机制原因 |
|---|---|
| 问"推荐理财"却念持仓 | 宽规则 `/理财/` 抢在窄规则前 → **抢答** |
| "找到了"听不懂 | 短语脱离上文无信号 → 只能靠话题白名单（已补 5 条） |
| "给小王转200"失败 | 语序没列 → **覆盖度靠手写** |
| "帮我留3000交学费"金额丢失 | 槽位抽取靠单条正则 → **脆弱** |

可以继续补第 30、50 条规则，但这条路只会"越来越长"，不会"越来越聪明"。

## 先量化，再谈优化

`docs/intent_cases.json` 是意图评测集（当前 34 条），`scripts/js_harness.mjs --intent` 逐句跑，
`smoke.py` 的「意图.评测集 N 条全部落对」是闸门。

两个指标要分开看：

1. **落对率**：句子 → 期望工具，命中即对。当前 34/34。
2. **危险误判率**：把 A 工具认成 B 工具、且 B 会动钱（例如"取消订阅"被认成"转账"）。**这个必须是 0**，比落对率优先。

评测集里的 `clarify` 用例（"理财"、"订阅"、"卡"）是**故意**要求反问的：这类只说了名词、没说动作的输入，猜错方向的代价比多问一句高得多。

## 三层演进

### 第一层：把"查表"变稳（现在）

- 评测集 + 闸门：任何改动都要过 34 条，抢答立刻暴露；
- **不确定就问**：`clarify` 工具，只给名词时反问，并给两个按钮（"查我的理财"/"推荐几个产品"）；
- 规则分级：特定意图在宽意图之前（顺序即优先级，靠评测集守住）。

### 第二层：换掉意图层（需要联网 / key）

把 `parseIntent()` 换成一个**适配器**，LLM 只做"翻译"，不做决定：

```js
// 契约：输入一句话，输出意图；任何异常都返回 null（回退到规则层）
async function llmIntent(text, { tools, timeoutMs = 3000 }) {
  // tools 由 docs/capabilities.json 生成，模型只能从中选，不能发明
  // 要求模型输出严格 JSON：{"tool":"...","params":{...},"confidence":0~1}
  // 外面必须做：JSON Schema 校验 → 工具白名单 → 参数类型校验 → 置信度阈值
}
```

三条硬规则：

1. **白名单**：模型只能从 `capabilities.json` 的 23 个工具里选，输出别的直接丢弃；
2. **阈值**：`confidence < 0.6` → 转 `clarify` 追问，不猜；
3. **兜底**：超时、解析失败、校验不过 → 回退规则层，而不是报错或瞎猜。

**判定 / 确认 / 执行 / 审计四层一行不改**——这是第一天画的边界，也是"模型被骗也转不走钱"的依据。

### 第三层：混合路由 + 录放（比赛后）

- 高频确定句式走规则（快、稳、零成本），长尾走 LLM；
- 演示用 **record/replay**：把 LLM 响应录成 `docs/llm_replay.jsonl`，按输入哈希回放，
  **断网也能演**，且响应可审计、可复现；
- 评测集扩到 200 句，按场景分层标注（转账/账单/订阅/卡片/联动/理财/无障碍/澄清）。

## 已经落地了什么（v0.13.0）

不是规划，是能跑的成品。

### 1. 混合路由（页面侧）

```
用户一句话
   ↓
① 规则层 resolveIntent()      ← 快、离线、可解释；命中就用它
   ↓ 认不出
② 意图服务 POST /intent       ← LLM（有 key）或回放（无 key）
   ↓ 返回前过三关：ok / 工具白名单 / 参数类型 / confidence ≥ 0.6
③ dispatchIntent()            ← 判定 → 确认 → 执行 → 审计（与规则层同一条管线）
```

关键点：**适配器只产出意图，进不了判定与执行**。它给的 `transfer` 一样要过额度规则、一样要确认。

### 2. 意图服务（`scripts/intent_service.mjs`）

| 能力 | 实现 |
|---|---|
| 真实模型 | `BANK_LLM_API_KEY` 存在时走 OpenAI 兼容接口，`temperature=0`，强制 JSON |
| 离线回放 | 无 key 时读 `docs/llm_replay.jsonl`，按归一化文本哈希命中 |
| 白名单 | 工具必须来自 `docs/capabilities.json`，模型不能发明能力 |
| 参数校验 | 金额必须整数分且 ≥0、人数 ≥2、对象名 ≤12 字符 |
| 置信度 | <0.6 返回 `low_confidence`，调用方**反问**而不是猜 |
| 超时兜底 | 2.5s 超时、解析失败、服务没起 → 一律回退规则层 |

启动：

```powershell
node scripts/intent_service.mjs 8791                  # 回放模式，断网可用
$env:BANK_LLM_API_KEY="sk-..."; node scripts/intent_service.mjs 8791   # 真实模型
```

页面里 `ADAPTER_URL` 指向 `http://127.0.0.1:8791/intent`；服务没起时页面照常工作（只是长尾句子会落到"没听懂"）。

### 3. 端到端实测

```
卡里还有多少         → query_balance（规则认不出 → 服务命中回放）
这个月我都在哪儿花钱了 → audit_leak（规则直接命中，没走服务）
帮我把那笔钱转给老李   → 追问金额（规则命中但缺槽位，不猜）
今天天气怎么样         → 没听懂（服务 ok:false，不瞎猜）
```

### 4. 回放文件的诚实说明

`docs/llm_replay.jsonl` 里的条目是**手写样例**，用来代替真实录制——机制是真的（按哈希命中、schema 校验、阈值拦截），内容不是真实模型输出。有 key 之后，把真实响应按同样格式落盘即可无缝替换。

## 仍然没做的

1. **真实模型没跑过**：本机没有 key，`fromLlm()` 的代码路径只有类型与结构保证，没有真实调用验证；
2. **回放集只有 8 条**：覆盖面窄，真实录制后才能扩到 200 条；
3. **没有缓存与批处理**：每句都打服务，成本与延迟未优化。

这三条写进自述的"不足"。

## 为什么不把规则层整个删掉

1. **离线硬约束**：演示必须断网可跑，服务不是永远在；
2. **可回归性**：规则层能被 136 条断言完全覆盖，LLM 的随机性会让"演示可复现"失效；
3. **成本**：高频句（查余额、查账单）走规则是零成本，没必要问模型。

所以定位是：**规则层是高速路与离线兜底，适配器是长尾出口**。两句话都要写进自述，而不是只说"我们用了大模型"。

## 验收标准（升级后仍要满足）

| 项 | 门槛 |
|---|---|
| 落对率（34 条基线） | ≥ 95%，且不得低于当前 100% |
| 危险误判率 | **0** |
| 断网可用 | 录放模式可完整演示 |
| 判定/执行层改动 | 0 行 |
