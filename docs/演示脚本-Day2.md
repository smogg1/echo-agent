# Day 2 演示脚本（双通道 / 外部服务 / 渠道）

## 一、双通道授权（最值得看的一段，约 2 分钟）

需要**两个浏览器窗口**，都打开 `app/index.html` 与 `app/family.html`。

1. 老人端输入 `转给小王 300 元` → 出现 🟡 确认卡
2. 点 **让家人确认** → 卡片里出现 **6 位口令**（例：`482913`）与 2 分钟倒计时
3. 把口令念给"家人"（另一个窗口打开 `app/family.html`）——**家属端页面上看不到这笔操作的内容**
4. 家属端独立填写：口令 `482913`、金额 `300`、收款人 `小王` → 点「核对无误，生成授权回执」→ 得到 6 位回执
5. 老人端把回执填进输入框 → **提交回执** → 执行成功，审计日志出现蓝色 `confirmed_by_family`，actor 是 `family-proxy`

**反例（这一步最能说明设计意图）**：
- 家属端把金额填成 `3000` → 回执与老人端不一致 → 老人端提示"回执不符（1/3）"，钱一分没动
- 意思是：**家属不看老人转述、自己填多少，决定了这笔钱能不能出去**
- 连续错 3 次 → 授权作废，审计记 `family_blocked`

## 三、外部服务（汇率）

```powershell
# 终端 1：起服务（同时提供页面，同源免 CORS）
cd D:\WorkSoftware\dsh\echo-agent
python scripts/fx_server.py
# 浏览器打开 http://127.0.0.1:8787/index.html
# 问：100 美元是多少人民币  → "按 1 美元 ≈ 7.12 元，100.00 美元 ≈ 712.00 元人民币"
```

然后 **Ctrl+C 停掉服务**、刷新页面、再问同一句：

> 汇率服务暂时不可用（2 秒超时后已降级）。查询余额、转账、查账单都不受影响，稍后再问我就行。

这就是"外部服务挂掉，内置工具照常"的证据。

## 四、渠道（IM / APP 网关的替身）

```powershell
cd D:\WorkSoftware\dsh\echo-agent
node scripts/webhook.mjs 8790

# 另开一个终端：
curl.exe -s -X POST http://127.0.0.1:8790/webhook -H "content-type: application/json" -d "{\"text\":\"查一下余额\"}"
```

返回：

```json
{"level":"green","reply":"当前余额：10,000.00 元（卡号 ****1234）","audit":{...}}
```

要点：`level` 就是三色判定的结果；渠道层只转发、不做判定，规则只有一份（页面里那份）。
